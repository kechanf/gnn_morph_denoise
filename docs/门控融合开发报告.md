# 门控融合（Conflict-Aware Gating）开发报告

## 一、背景与动机

在 Graph-Mamba（GPS）架构中，每一层同时包含**局部 GNN**（如 GatedGCN）和**全局 Mamba** 两个分支：

- **GNN**：基于边结构的局部消息传递，擅长几何/拓扑信息。
- **Mamba**：基于序列的全局建模，擅长长程依赖。

默认融合方式为**简单相加**：

\[
h = h_{\text{local}} + h_{\text{attn}}
\]

当两路输出在部分维度上**不一致**（例如 Mamba 对某节点给出与 GNN 差异较大的表示）时，直接相加可能放大噪声或冲突，影响下游分类。门控优化的目标是：**根据两路输出的逐维冲突程度，自适应地决定更信任哪一路**，在冲突大的维度上偏向局部 GNN，在一致的维度上保留 Mamba 的长程信息。

---

## 二、思路与设计

### 2.1 核心思想

- **逐维（channel-wise）门控**：对每个特征维度单独计算一个权重 \(\alpha_d \in [0,1]\)，再做凸组合：
  \[
  h_{\text{fused},d} = \alpha_d \cdot h_{\text{mamba},d} + (1-\alpha_d) \cdot h_{\text{gnn},d}
  \]
- **冲突度量**：用两路输出的逐维平方差 \(\Delta_{\text{diff}} = (h_{\text{mamba}} - h_{\text{gnn}})^2\) 表示该维度上的“冲突”大小；冲突大时，希望 \(\alpha\) 变小，即更信任 GNN。
- **可学习门控 + 冲突偏置**：门控由 MLP 根据拼接特征 \([h_{\text{mamba}}; h_{\text{gnn}}]\) 预测一个 logit，再减去 \(\beta \cdot \Delta_{\text{diff}}\) 作为偏置，使冲突大时 logit 减小，经 Sigmoid 后 \(\alpha\) 减小：
  \[
  \alpha = \sigma\big(\text{MLP}([h_{\text{mamba}}; h_{\text{gnn}}]) - \beta \cdot \Delta_{\text{diff}}\big)
  \]
  其中 \(\beta \geq 0\) 控制“冲突惩罚”的强度，可为固定值或可学习参数。

### 2.2 设计要点

| 项目 | 说明 |
|------|------|
| 凸组合 | \(\alpha \in [0,1]\) 保证输出是两路的凸组合，数值稳定。 |
| 逐维 | 不同维度可有不同 \(\alpha\)，比全局标量门控更细粒度。 |
| 可选 | 通过配置 `gt.fusion` 在 `sum`（默认）与 `conflict_aware` 间切换，不启用时行为与原版完全一致。 |

## 三、实现方法

### 3.1 公式与算法

1. 输入：\(h_{\text{mamba}}, h_{\text{gnn}} \in \mathbb{R}^{N \times D}\)。
2. 拼接：\(z = [h_{\text{mamba}} \| h_{\text{gnn}}] \in \mathbb{R}^{N \times 2D}\)。
3. 门控 logit：\(\text{gate\_logit} = \text{Linear}_{2D \to D}(z)\)。
4. 冲突：\(\Delta_{\text{diff}} = (h_{\text{mamba}} - h_{\text{gnn}})^2\)。
5. 门控系数：\(\alpha = \sigma(\text{gate\_logit} - \beta \cdot \Delta_{\text{diff}})\)。
6. 输出：\(h_{\text{fused}} = \alpha \odot h_{\text{mamba}} + (1 - \alpha) \odot h_{\text{gnn}}\)。

### 3.2 代码位置与结构

| 文件 | 作用 |
|------|------|
| `external/Graph-Mamba/graphgps/layer/fusion_gating.py` | **ConflictAwareFusion** 模块：Linear(2*dim→dim)、可选的可学习 \(\beta\)、`gate_init_zero` 零初始化；`forward(h_mamba, h_gnn)` 实现上述公式。 |
| `external/Graph-Mamba/graphgps/layer/gps_layer.py` | **GPSLayer**：在 `__init__` 中根据 `cfg.gt.fusion` 创建 `self.fusion_module`（ConflictAwareFusion 或 None）；在 `forward` 末尾，若 `fusion_module is not None` 且有两路输出，则调用 `fusion_module(h_attn, h_local)`，否则 `h = sum(h_out_list)`。 |
| `external/Graph-Mamba/graphgps/config/gt_config.py` | 默认配置：`cfg.gt.fusion = 'sum'`，`cfg.gt.fusion_beta = 1.0`，`cfg.gt.fusion_gate_init_zero = False`。 |

### 3.3 关键代码片段

**fusion_gating.py（核心计算）：**

```python
def forward(self, h_mamba: torch.Tensor, h_gnn: torch.Tensor) -> torch.Tensor:
    z = torch.cat([h_mamba, h_gnn], dim=-1)
    gate_logit = self.gate_net(z)
    diff = (h_mamba - h_gnn).pow(2)
    alpha = torch.sigmoid(gate_logit - self.beta * diff)
    h_fused = alpha * h_mamba + (1.0 - alpha) * h_gnn
    return h_fused
```

**gps_layer.py（分支与调用）：**

```python
# __init__ 中
fusion_type = getattr(cfg.gt, 'fusion', 'sum')
if fusion_type == 'conflict_aware':
    self.fusion_module = ConflictAwareFusion(dim_h, beta=..., gate_init_zero=...)
else:
    self.fusion_module = None

# forward 末尾
if self.fusion_module is not None and len(h_out_list) == 2:
    h = self.fusion_module(h_out_list[1], h_out_list[0])  # (h_mamba, h_gnn)
else:
    h = sum(h_out_list)
```

注意：`ConflictAwareFusion` 的接口为 `forward(h_mamba, h_gnn)`，而 `h_out_list[0]` 为 GNN、`h_out_list[1]` 为 Mamba，故调用时传入顺序为 `(h_out_list[1], h_out_list[0])`。

### 3.4 配置项说明

| 配置键 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `gt.fusion` | str | `'sum'` | 融合方式：`sum` = 简单相加；`conflict_aware` = 逐维门控。 |
| `gt.fusion_beta` | float | 1.0 | 冲突项系数 \(\beta\)；ConflictAwareFusion 中可为可学习参数。 |
| `gt.fusion_gate_init_zero` | bool | False | 为 True 时 gate 的 Linear 零初始化，初始 \(\alpha \approx 0.5\)（两路等权）。 |

## 四、调用方法

### 4.1 适用模型

门控融合**仅在使用 GPS 层（GatedGCN + Mamba）时生效**，即：

- 配置为 **Baseline A（10+10）**：`model.type: GPSModel`，`gt.layer_type: CustomGatedGCN+Mamba_*`。
- **不适用于** Baseline B（纯 GatedGCN-only），因 B 无 Mamba 分支，不存在两路融合。

### 4.2 通过 YAML 配置

在 `external/Graph-Mamba/configs/Mamba/morphology-node-EX.yaml` 中（或继承该配置的 yaml）设置：

```yaml
gt:
  fusion: conflict_aware
  fusion_beta: 1.0
  fusion_gate_init_zero: false
```

### 4.3 通过命令行 override

在项目根目录使用 `scripts/run_graph_mamba.py` 时，用 `--override` 传入（无需改 YAML）：

```bash
python scripts/run_graph_mamba.py \
  --data_dir /path/to/synthesis_data \
  --wandb False \
  --name_tag full_gating_run \
  --repeat 1 \
  --override gt.layers 10 \
  --override gt.fusion conflict_aware \
  --override gt.fusion_beta 1.0
```

可选：若希望初始阶段两路更均衡，可加：

```bash
  --override gt.fusion_gate_init_zero True
```

### 4.4 数据与环境

- **数据**：与两种 baseline 相同，指向包含 `.pt` 图数据的目录（如 synthesis_data）。
- **环境**：需安装 **mamba-ssm**（Baseline A 必须），且不能使用 `--no-mamba`。

### 4.5 完整示例（复制即用）

```bash
export GNN_DATA_ROOT=/path/to/your/data_root

python scripts/run_graph_mamba.py \
  --data_dir /path/to/synthesis_data \
  --wandb False \
  --name_tag conflict_aware_gating \
  --repeat 1 \
  --override gt.layers 10 \
  --override gt.fusion conflict_aware \
  --override gt.fusion_beta 1.0
```

结果与 checkpoint 会写入 `$GNN_DATA_ROOT/graph_mamba_results/` 下对应 `name_tag` 的子目录。

## 五、参考结果与说明

- 在**全量 2000 图、200 epoch** 的形态学节点分类上，启用门控融合（conflict_aware）后，**Val acc ≈ 88.9%，Test acc ≈ 88.6%**，与 Baseline A（10+10，sum 融合）的 88.21% / 88.14% 同量级或略高，可作为可选优化保留。
- 未启用时（`gt.fusion: sum`）行为与原始 Graph-Mamba 完全一致，不影响既有 baseline 复现。

## 六、小结

| 项目 | 内容 |
|------|------|
| **功能** | 在 GPS 层内用逐维门控替代“GNN + Mamba”的简单相加，冲突大时更信 GNN。 |
| **思路** | 用 \((h_{\text{mamba}}-h_{\text{gnn}})^2\) 作冲突度量，Sigmoid(logit - β·冲突) 得到 α，凸组合融合。 |

| **配置** | `gt.fusion`、`gt.fusion_beta`、`gt.fusion_gate_init_zero`（见上表）。 |

以上即为门控融合的完整开发报告，便于后续维护、复现与扩展（如固定 \(\beta\)、其他冲突度量等）。
